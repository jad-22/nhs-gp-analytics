# Product

## Register

product

## Users

Primary audience: portfolio reviewers and hiring managers evaluating engineering, data science, and product craft. Secondary audience: healthcare analysts or technically literate users who want to explore NHS GP registration data. Users arrive with curiosity, not a specific task — they want to be impressed by the depth and clarity of the analysis, and to trust the data they're seeing.

## Product Purpose

A publicly hosted analytics dashboard that visualises NHS England GP practice registration data across three analytical dimensions: list size trends (time series + forecasting), clinical system market share (EMIS vs SystmOne), and deprivation analysis (IMD + geographic clustering). Backed by a fully automated monthly data pipeline. Success means: a hiring manager opens it and immediately understands both the analytical depth and the engineering quality behind it.

## Brand Personality

Modern · Minimal · Evidence-based. The data speaks; the UI creates the conditions for it to be heard. Think Observable or Datawrapper — not a hospital, not a BI vendor.

## Anti-references

- **Generic Streamlit**: grey sidebar, stock Arial font, default Plotly blue. Must look intentionally designed.
- **GOV.UK / NHS.uk**: GDS palette, blue/white government aesthetic, public-sector officialness. This is a portfolio piece, not an official NHS product.
- **Corporate BI tools (Tableau / Power BI)**: navy headers, KPI card grids, logo in the corner, dashboard-by-committee feel.

## Design Principles

1. **Data before decoration** — Every visual element must earn its place by aiding comprehension. If it doesn't clarify the data, it doesn't belong.
2. **Understated authority** — Excellence shows through typographic precision, consistent spacing, and intentional chart design — not through visual flair or decoration.
3. **Portfolio signals through craft** — The dashboard must look like it was built by someone who thinks carefully about design. The signal is in the details: hierarchy, rhythm, colour restraint, chart quality.
4. **Evidence-first structure** — Each page guides the user through a data story, building from overview to drill-down. Sections earn the user's attention progressively.
5. **Question every default** — Streamlit, Plotly, and Python all have defaults that produce generic output. Every default must be consciously accepted or overridden.

## Accessibility & Inclusion

WCAG 2.1 AA as a practical baseline. Colour-blind-safe chart palettes (avoid red/green encoding of meaning). No specific formal requirement — optimise primarily for visual impression and analytical clarity.
